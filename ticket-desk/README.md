# Ticket 台（个人任务计时器）

`python server.py` → http://localhost:8730/ （端口用环境变量 `TICKET_PORT` 改，
数据文件用 `TICKET_DATA` 改，默认落本目录的 `tickets.json`。）

Python 3.8+，零第三方依赖，只绑 `127.0.0.1`，数据只在本机。

一句话：记下每个任务的**下达时刻**，一个按钮开始/暂停秒表，子 ticket 的时间自动并进父级，
**重叠不重复计**。完成后可归档。

---

## 一、时间口径（这是全系统唯一需要动脑的地方）

**不存"累计秒数"，只存运行区间。** 每个 ticket 有

```json
"sessions": [[开始秒, 结束秒|null], ...]     // null = 此刻正在跑
```

- **自身耗时** = 自己 sessions 的并集长度
- **子树耗时**（行上那个大时钟） = 自己 + 全部后代的 sessions **合起来取并集**的长度

并集 = 集合测度，于是：

| 情况 | 结果 |
|---|---|
| 两个子 ticket 同时在跑 1 小时 | 父只加 **1 小时**，不是 2 小时 |
| 父自己在跑，同时子也在跑 | 重叠那段**只算一份** |
| 子 A 跑 10:00-10:30、子 B 跑 10:20-11:00 | 父记 **60 分**（并集 10:00-11:00），不是 70 分 |
| 子 A 跑 10:00-10:20、子 B 跑 10:40-11:00 | 父记 **40 分**（两段不相接，各算各的） |

用"累加秒数"的实现做不到这件事——这就是为什么这里存区间而不是计数器。
计算在前端 `unionSec()`（`index.html`），后端只忠实记录区间，不做加总。

有子 ticket 的行会额外显示灰色的 `自 mm:ss` = 该 ticket 自己的时间，方便看出
"父这条线自己花了多少 / 子占了多少"。

## 二、状态机

| 状态 | 点 | 怎么进 | 显示 |
|---|---|---|---|
| 未开始 todo | 灰 | 新建 | 下达时刻（**一律带日期**，跨年再补年份） |
| 工作中 working | 蓝（呼吸） | ▶ 开始 | 时钟每秒走 + "本轮 x:xx" |
| 暂停 paused | 粉 | ⏸ 暂停 | **暂停于 M/D HH:MM** |
| 完成 done | 灰绿 + 删除线 | ✓ 完成 | **完成于 M/D HH:MM** |

- ✓ 完成会自动收掉正在跑的区间（不会留下永远在跑的僵尸计时）。
- `↩ 未完成` 退回：有过工时 → 暂停，从没跑过 → 未开始。
- `归档` 只对已完成开放，**连同整棵子树**一起归档；归档区在页面底部折叠，`取出` 可还原。

## 三、操作

| 想干嘛 | 怎么做 |
|---|---|
| 新建 | 顶部输入框回车 |
| 建子 ticket | 行上 `＋子` → 行下出现内联输入框，回车可连着建多个，Esc 关闭 |
| 改名 | **双击标题**，回车保存 / Esc 取消 |
| 删除 | `✕` → 变红「确认删?」再点一次（连同子 ticket）；点别处取消 |
| 换位置 | 抓 `⣿` 上下拖，**只在同一层内**重排（跨层会被拒，避免误拖丢层级） |
| 让 Claude 建 | 对 Claude 说「给这个对话建个 ticket，标题 xxx」→ `/ticket` skill（见第五节） |
| 改层级 | `⇥` 降为上一个同层 ticket 的子级；`⇤` 升一层 |
| 换配色 | 右上角 `◐` 在「跟随系统 / ☀ 浅色 / ☾ 深色」之间循环 |

### 配色

页面**默认跟随系统**，所以在一台深色模式的电脑上打开是深色版，而不是浅色的粉+天蓝那套。
想固定成某一套，点右上角 `◐`：三档循环，选择存在 `localStorage`（`theme` 键），刷新后还在。
应用主题的那几行脚本放在 `<head>` 里、`<body>` 渲染之前跑，否则会先闪一下系统主题再跳过来。

顶部统计：在跑几个 / 未完成几个 / **今日总时长**（同样是并集，今天 00:00 之后的部分）。

## 四、实现与硬规矩

- `server.py`：标准库 `ThreadingHTTPServer`，只绑 `127.0.0.1:8730`；`tickets.json` 原子写
  （写 `.tmp` 再 replace）。JSON 读坏了不覆盖，改名成 `tickets.broken.<ts>.json` 留证据。
- 前端每秒只改文本、不重绘 DOM，所以拖动和编辑不会被时钟打断；每 20 秒拉一次全量做多标签页同步
  （正在编辑或拖动时跳过）。
- 时钟用**服务器时间**校正（`SKEW = server.now - client.now`），避免浏览器时钟偏差影响读数。
- 不用 `alert/confirm/prompt`：模态框会卡住页面（也挡住自动化）。删除用二次点击，新建子用内联输入。
- 数据只在本机，没有账号也没有外发。

### API（都在 `/api/`，POST 收 JSON，返回 `{ok, msg?, now, tickets}`）

| 路由 | 参数 |
|---|---|
| `GET /api/state` | — |
| `POST /api/create` | `title`, `parent?` |
| `POST /api/edit` | `id`, `title?`, `note?` |
| `POST /api/action` | `id`, `action` ∈ start / pause / done / undone / archive / unarchive |
| `POST /api/delete` | `id`（含整棵子树） |
| `POST /api/move` | `id`, `before`（同层，`null` = 移到该层末尾） |
| `POST /api/reparent` | `id`, `parent`（`null` = 升为顶层；禁止挂到自己的子孙下） |

`note` 字段（skill 用来存会话上下文）在页面上是**标题的悬停提示**，没有独立 UI。

## 六、计划时间（planStart / planEnd）

**纯参考值，不参与任何计时。** 它们不进 `sessions`，不影响子树时长、今日总时长、任何统计——
真正的耗时永远只由"开始/暂停"按出来的运行区间决定。

- 新建时：输入框右边的 **📅** 打开面板，勾选「计划开始」和/或「计划结束」，用**滚轮**（上下滑动、
  鼠标滚轮、直接点某一项都行）选日期/时/分。两个各自独立，可以只设一个。不勾 = 不设。
- 已有 ticket：行上有计划就点那个 **📅 徽章**，没有就 hover 出 **📅** 按钮。面板里「清空」= 两个都取消。
- **默认停在"现在的下一个整点"**（18:47 打开 → 19:00），少滑几下。
- 显示：`📅 8/24 09:00 → 11:30`（同一天时第二个只显示时间）／`📅 8/24 09:00 起`／`📅 8/24 11:30 前`。
- 过了计划结束还没标完成 → 徽章变粉，只是提醒，不做任何拦截。
- 计划结束早于开始也允许（会提示一句），因为它只是写给自己看的参考。

滚轮的项高写死在两处（CSS `.wheel .it{height:26px}` 与 JS `const ITEM = 26`），改一处必须改另一处。

命令行侧（skill）：`--plan-start "8/24 09:00"` / `--plan-end "明天 11:30"`，
也认 `"09:00"`（今天）与 `今天/明天/后天 HH:MM`。

## 五、Claude 侧的入口：`ticket` skill

仓库里的 `ticket-desk/claude-skill/`（`SKILL.md` + `ticket.py`）。装法：把这个目录
拷贝（或做符号链接）成 `~/.claude/skills/ticket/`，脚本会先按 `TICKET_DESK_DIR` 环境变量、
再按仓库相对位置、最后按同目录的 `desk_path.txt` 去找 `server.py`。

对 Claude 说「给这个对话建个 ticket，标题 xxx」，它就建好并**立刻开始计时**（说"先登记着"才不启动），
`--note` 里带当前会话的 cwd 与在干嘛，页面上**悬停标题**即可看到。服务没跑会被 pythonw 静默拉起
（先探端口，不双绑）。

也可直接命令行用：

```
python ~/.claude/skills/ticket/ticket.py add "标题" [--parent 关键词] [--todo] [--note "..."] [--plan-start "8/24 09:00"] [--plan-end "明天 11:30"]
python ~/.claude/skills/ticket/ticket.py start|pause|done|undone|archive "标题关键词"
python ~/.claude/skills/ticket/ticket.py list [--all]
```

关键词按标题子串匹配，命中多条会列出候选而不是瞎猜。脚本**故意没有 delete** —— 删除只走页面上的二次确认。
